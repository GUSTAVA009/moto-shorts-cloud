# HAPYCH Voice Studio — закрытая облачная озвучка для YouTube-каналов

## Фактический статус

- Написаны сайт, закрытая панель, аутентификация, раздельные API-ключи и голосовые профили.
- Подготовлен безопасный запуск CPU-модели Qwen3-TTS на ARM64 Linux в облаке.
- Проверка функций проводилась тестами без живой VM, реальный российский WAV ещё не подтверждён.
- Oracle Cloud VM, HTTPS, DNS voice.hapychrust.ru и TTS-генерация на сервере ещё НЕ развёрнуты.
- Компьютер владельца и NVIDIA GPU НЕ используются; сторонний платный TTS исключён.

## Минимум 330 роликов в месяц

К каждому действующему заводскому YouTube-каналу привязан целевой выпуск не менее 330 уникальных QA-проверенных MP4 и подтверждённых доставок в календарный месяц. 12 в сутки дают 336 за 28 дней, 360 за 30 и 372 за 31. При отставании планировщик может использовать до 16 окон в сутки с интервалом 90 минут, не превышая одновременно 10 постов в бесплатной очереди Buffer. Это целевой объём, НЕ подтверждение фактических 330 готовых роликов. Любые работы по озвучке, историям и рендерам не засчитываются как опубликованные Shorts. Количество готовых материалов зависит от новых лицензированных сюжетных кадров, ASR и проверки качества.

## Бесплатный облачный вариант (без локального ПК)

Официальная программа Oracle Cloud Always Free Ampere A1 Flex: 1500 OCPU-часов и 9000 GB-часов в месяц (при непрерывной работе приблизительно 2 OCPU и 12 ГБ RAM). GPU нет. Регистрация предусматривает проверку платёжной карты. Доступность инстансов не гарантируется; простаивающие Always Free ресурсы могут быть освобождены. 4 OCPU и 24 ГБ RAM из устаревших сторонних инструкций нельзя считать бесплатно доступными без независимой проверки.

Официальные условия: https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm
Открытый CPU сервер: https://github.com/TrinityTF/qwen3-tts-server
Собственно C-движок: https://github.com/TrinityTF/qwen3-tts

Насколько быстро именно 2 OCPU озвучат 12+ роликов, проверяется только живым запуском. Статистика скорости стороннего проекта на 4 OCPU не является гарантией бесплатного тарифа. Для целей пользователя критична суточная производительность и месячный выпуск, а не задержка одного аудио.

## Разные YouTube-каналы

Каждый зарегистрированный канал имеет отдельный slug, зафиксированный voice_id, исходный WAV с SHA-256, отдельные gvk_ ключи и собственный учёт запросов. Ключ канала A не позволяет синтезировать голос канала B. Владелец может выпускать несколько ключей одному каналу, менять лимиты и отзывать их; все ключи имеют 256 бит случайности и хранятся только хешами.

В конфигурации ARM CPU используются не более пяти различных мужских готовых пресетов Qwen3-TTS 0.6B CustomVoice. Это доступные веса модели, а НЕ эксклюзивно созданные и обученные персональные дикторы. Настройки тембра и характера в панели фиксируют желаемый профиль и подачу, но CPU CustomVoice не обучается на новом аудио при каждом запросе. Для настоящего индивидуально разработанного голоса понадобится отдельная модель и ресурсы. Нативный русский язык, отсутствие акцента и разборчивость оцениваются живой ASR-проверкой перед публикацией.

## Настройка VM (только на облачном ARM64 Ubuntu)

1. Создать собственную Oracle Always Free ARM VM с 2 OCPU и 12 GB RAM. Не активировать платное превышение. Никогда не открывать в публичных правилах OCI порты 8000/8001/8002/8080.
2. Установить на VM Git, Python 3, Docker Engine и Docker Compose. Скопировать репозиторий на эту облачную VM, перейти в папку voice-studio.
3. Скопировать .env.example в локальный .env и заполнить ДВА разных длинных секрета для владельца и сессий. Секреты не отправлять в чат и не публиковать в Git.
4. На VM запустить bash ./bootstrap-oracle-arm.sh. Наш патчер проверяет исходный upstream setup.sh, отключает его открытые порты и изменяет C socket на loopback ещё ДО компиляции. При несовпадении исходного файла установка останавливается.
5. После подтверждения CPU HTTP на 127.0.0.1:8002 выполнить docker compose up -d --build и curl -f http://127.0.0.1:8080/login.
6. Настроить DNS/HTTPS поддомен voice.hapychrust.ru (если он контролируется владельцем), использовать Caddyfile.example как пример HTTPS proxy. Дополнительно ограничить административный интерфейс через Cloudflare Access. Нужны собственные права на DNS и саму VM; эти действия пока не выполнены.

ВАЖНО: не запускайте upstream setup.sh прямо из чужого репозитория: он в исходной версии открывает внешний HTTP порт 8000 и слушает 0.0.0.0. Скрытая модель не должна быть доступна публично. Не создавать облачную VM за плату.

## API и публикация

Один клиентский запрос: POST https://voice.hapychrust.ru/v1/audio/speech
Заголовки: Authorization: Bearer gvk_... и X-Idempotency-Key: unique-episode-001
Тело JSON для первого канала: {"channel_slug":"gustava","voice":"gustava-original-v1","text":"Дорога только начинается!","speed":1.0,"response_format":"wav"}
Для другого канала: другой gvk_ ключ, другое channel_slug и voice_id, например hapych-motorcade-original-v1.

Возвращаются WAV и заголовки X-Voice-ID, X-Channel-ID, X-Audio-SHA256, X-Reference-SHA256. Повтор с тем же idempotency key и текстом возвращает сохранённый WAV. Противоречивый повтор отклоняется; чужой канал отклоняется 403.

Получить аудио недостаточно: до публичной отправки завод обязан подтвердить источники кадров, русское распознавание речи, синхронность, монтаж, визуальный просмотр, SHA файла и реальный Buffer Post ID. Зелёный GitHub Action не является подтверждением готового видео.
