# Независимая техническая рецензия GUSTAVA Shorts Factory

**Проверка:** 01.11.2026. Основание: активный GitHub `main`, GitHub
Actions, сохранённые в `render-ledger` квитанции, действующий канонический
контракт и последние отчёты Buffer. Проверка не подменяет независимый
доступ к YouTube Studio или живой монтажной станции.

## Вердикт

**Исследовательская beta-версия, НЕ подтверждённый автономный production.**
Кодовые regression-тесты проходят, но факт непрерывной поставки роликов
не подтверждён. Публиковать проект под названием «400 Shorts в месяц
гарантированно» или раздавать его как готовое решение нельзя.

## Найденные архитектурные риски

1. **Неверифицированные аудиосервисы.** Три ступени есть в коде, но
   без доступных HTTPS-хостов, разрешённого эталона и секретов остаются
   пассивной конфигурацией. Альтернативный Chatterbox может звучать
   иначе, поэтому не разрешать канарейку до личного прослушивания
   и сравнения с закреплённым диктором. No-op/пустой WAV запрещён.
2. **Дефицит лицензированных новых видеосцен.** Потребление двух
   самостоятельных исходников на Shorts требует до 800 новых кадровых
   клипов в месяц; закрытая крошечная ручная коллекция не способна
   гарантировать такую скорость. Понадобятся официальный Pexels API,
   больше независимых авторов, либо действительно оригинальная
   видео-съёмка/мультипликация с отдельными требованиями качества.
3. **Потенциально повторяющиеся тексты.** Комбинаторный генератор
   часто переставляет «первый взгляд», «подготовка», «детали».
   Сам факт текстовой уникальности не гарантирует интереса и
   выполнения правил YouTube по оригинальности.
4. **Фиксированная привязка к каналу.** GitHub-репозиторий содержит
   GUSTAVA YouTube ID и идентификаторы Buffer в коде. Клонирующий
   пользователь не должен публиковать в другой канал простым вводом
   ключа; сначала необходима корректная конфигурация и тесты.
5. **Память о реальных публикациях.** Не удалять `render-ledger`,
   `buffer-publication-receipts` и историю исходников: эти
   квитанции препятствуют повторным постам. Серверный HTTPS без
   постоянного хранилища не подходит для хранения голосовых профилей.
6. **YouTube-проверка отделена от Buffer.** `Buffer sent` ещё
   не доказывает общедоступный Shorts. Нужен независимый доступ к
   YouTube Studio/API для фиксации `video_id`, `publishedAt`,
   видимости и реального URL.
7. **Облачные лимиты.** Бесплатные GitHub Actions, Buffer и
   бесплатное облако могут менять доступность и лимиты. Объём 400/мес
   нельзя гарантировать только количеством запланированных cron.

## Что в архитектуре сделано правильно

- Отдельные стадии «сценарий», «лицензия», «оригинальная аудиодорожка»,
  «ASR до/после», «визуальный QA», «предварительный показ», «Buffer»,
  «публичный YouTube»; нет фиктивного зачёта прогресса.
- Сильные ограничения на дублирование видео, источник/автора,
  привязку канала и голосовую целостность.
- Пиннинг эталонного WAV и контрольные SHA-256; секреты не
  должны попадать в публичный репозиторий.
- Идемпотентные квитанции публикаций, защита от повторов с
  неопределённым результатом API.
- Факт редакционного отбора: «говорим о шлеме — показываем шлем»,
  не подменяем реальный сюжет случайным B-roll.
- Тесты `cloud-shorts/test_*.py`, `voice-studio/tests/test_*.py`
  и GitHub CI позволяют отлавливать регрессии до merge.

## Минимальные критерии для объявления «завод работает»

- **Не менее трёх подряд новых разных** эпизодов прошли
  лицензирование, реальную озвучку, исходный ASR, финальный смешанный
  ASR, визуальную проверку и сформировали уникальные MP4.
- Для каждого есть SHA, редакционное одобрение, Buffer Post ID,
  `sentAt` и подтверждённый публичный `youtube.com/shorts/ID`.
- Автоматическое пополнение после падения очереди с 10 до 9,
  а также аварийное при 0–1, запущено и дало **не просто сценарии,
  а новые MP4 и реальные посты**.
- Три голоса нельзя считать «резервом» по одной лишь конфигурации:
  измерены живой контрольный русский WAV и восстановление после
  недоступности основного сервиса. При ошибке SHA/голоса — отказ
  без публикации; при отсутствии трёх — красный статус.
- Полезные ограничения и реальные GitHub/Buffer квоты при
  14–16 публикациях в сутки проверены за несколько календарных дней;
  отставания отображаются честно.

## Примечание к публичной публикации GitHub

Репозиторий `GUSTAVA009/moto-shorts-cloud` **уже доступен публично**.
Публичность исходников не является меткой production-ready и
не подразумевает автоматического предоставления прав на копирование
чужих видео, голосовых эталонов или брендинга. Нельзя публиковать
приватные ключи, `.env`, образцы владельческих голосов и историю
личных файлов. Отдельный стабильный релиз `v1.0` желательно делать
**после выполнения критериев выше**, а не по зелёному тесту.
