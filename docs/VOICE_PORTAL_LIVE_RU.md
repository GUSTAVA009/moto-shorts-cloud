## Действительно работающие возможности интерфейса

Вход владельца по HTTPS, signed random cookie с HttpOnly/Secure/SameSite=Strict, сессия 8 часов, CSRF, защита от перебора, выход, смена пароля и сброс остальных сессий. Просмотр готовности облачного Qwen3 и закреплённого SHA референса, персональное название канала, сохранённый черновик текста, скорость 0.85–1.15, генерация **приватного** WAV из существующего API с контролем SHA/voice/ref, плеер и загрузка. Никакой автоматической смены Deep/эталона при настройке скорости; скорость — постобработка предпросмотра (ffmpeg atempo), не новая обученная модель.

**Явно не реализовано:** полноценное управление несколькими каналами и API-ключами Factory с сайта, управление расписанием Buffer, полноценная YouTube Studio Analytics, регистрация пользователей/почта, смена основной производственной модели через UI. В репозитории есть `voice-studio/app.py` (другая незапущенная ARM-бэкенд-архитектура), **его нельзя просто подменить на 8077 без адаптации к текущему Base Qwen**. Переключатели, не влияющие на реальную фабрику, не выдавать за рабочие. Текущий live-портал является персональным интерфейсом владельца, а не доказательством полностью восстановленного YouTube Factory.

## Проверки и восстановление

1. `systemctl is-active hapych-factory-portal.service hapych-factory-tts.service hapych-factory-voice-tunnel.service`; `curl -I https://voice.hapychrust.ru/login` (использовать GET для HTML) и `curl -fsS https://voice.hapychrust.ru/health`.
2. Если портал недоступен, проверить собственный systemd unit, порт `127.0.0.1:8078` и path rule Cloudflare, **не перезапускать существующий VPN и не удалять сервис 8077**.
3. Если смена маршрутизации ломает API, вернуть сохранённый `voice-tunnel.pre-portal-20261101.yml` и перезапустить **только выделенный** `hapych-factory-voice-tunnel.service`.
4. Деплой изменений: обновлять `live_portal.py` из проверенного Git commit; запускать `test_live_portal.py`; менять портал через `systemctl restart hapych-factory-portal.service` (TTS не трогать).
5. Держать обязательную точку восстановления Factory в `docs/FACTORY_RECOVERY_CHECKPOINT_RU.md` и issue #80, указывать run ID, SHA, состояния.

## Исправление смены пароля и эквалайзер (2026-11-01)

- По скриншоту владельца сервер выдавал `INVALID_CURRENT_OR_NEW_PASSWORD`, объединяя два разных случая: неверный текущий пароль и новый короче 14 символов. Кабинет теперь показывает точные русские пояснения, счётчик символов нового пароля, требует подтверждения нового значения и сообщает об успешной смене. Начальная секретная строка `INITIAL_OWNER_PASSWORD=<значение>` вводится только **после знака =**.
- После успешной смены сервер сбрасывает другие сессии и создаёт новый CSRF для *текущей* сессии; браузер заменяет код защиты без принудительного выхода. Это исправляет ошибку последующих сохранений после смены пароля. Новое значение хранится только в PBKDF2-соли/хеше, секреты не пишутся в лог.
- В личный кабинет добавлен **реальный пятиполосный эквалайзер озвучки**: 80 Гц, 250 Гц, 1 кГц, 3 кГц, 8 кГц, каждый от −6 до +6 дБ; режимы нейтральный/глубже/тёплый баритон/чёткая дикция, ручная регулировка и сброс. Уровни сохраняются с настройками канала в приватной `preferences.json`, загружаются повторно и передаются для каждой новой **приватной** генерации WAV.
- Сигнал действительно обрабатывается в `generate_job` безопасными FFmpeg equalizer-фильтрами из allowlist частот/уровней, после них применяется limiter. При нулевых 5 полосах и скорости 1× исходный WAV не перекодируется. Никаких произвольных FFmpeg-команд от браузера. Идентификатор голоса, закреплённый reference SHA и production API на 8077 не меняются, EQ **не действует** на публикации YouTube Factory.
- Старые вкладки без поля `eq` продолжают работать: сохранённый EQ не сбрасывается при их сохранении. Некорректный, инъекционный или выходящий за диапазон EQ запрос отклоняется HTTP 422.
- Интеграционные тесты в `voice-studio/tests/test_live_portal.py`: 7 проверок на Linux VPS, включая реальное преобразование WAV и увеличение 80-Гц сигнала при +4 дБ с контролем отсутствия клиппинга. Не считать тест эквалайзера доказательством воспроизведения точного Deep тембра.

**Проверка после релиза:** HTTPS `/studio` после входа отображает 5 ползунков и поле подтверждения пароля. Сохранить EQ, обновить вкладку, убедиться в сохранении, сгенерировать сравнимый оригинал (все 0) и EQ WAV, проверить звук, затем изменить пароль новым >=14-символьным значением и убедиться, что новая сессия продолжает сохранять настройки. Реальный ввод пароля должен выполнять владелец: не читать хеши и не генерировать пароль без его запроса.


**Фактическое развёртывание и live-canary:** обновлённый `live_portal.py` атомарно установлен на существующий VPS с сохранением backup `/opt/hapych-factory-voice/live_portal.before-password-eq-20261101.py`; перезапущен только `hapych-factory-portal.service`. Проверка реального HTTPS: `/login=200`, анонимная `/studio=303`, `/health=200` и `tts_ready_for_private_request=true`; все три отдельные службы (`portal`, `tts`, `voice-tunnel`) остались активны.
