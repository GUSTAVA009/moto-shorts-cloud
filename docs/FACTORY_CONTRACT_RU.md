# Единый контракт «Автоматизированный завод YouTube» — GUSTAVA Enduro

**Источник истины для будущих чатов, ChatGPT, Claude Code, Codex, OmniRoute и любых агентов.** Машиночитаемая версия: [factory_contract.json](../cloud-shorts/factory_contract.json). Перед любыми изменениями обязательны `AGENTS.md`, этот файл, последний CI-отчёт и реальный журнал Buffer. История других чатов не заменяет эти правила. Для изменений стратегического направления требуется явное новое решение владельца. Файл хранится в GitHub и проверяется CI.

## 1. Канал и приоритеты
Это **GUSTAVA Enduro**, YouTube ID `UCS0QCodPcFBTjMt4ioEWOUw`, `@gustava009`. **MOTOBRATR `@motobratr1` — отдельный проект**: запрещено смешивать метрики, исходники, публикации, права и токены. Цель: до 10 **новых оригинальных** Shorts в день, планирование примерно через 90 минут, без повторов, с честной обратной связью и без гарантии монетизации или охватов. Количество не оправдывает брак.

## 2. Не путать десять разных сущностей
`Сценарий` ≠ `проверенный исходник` ≠ `подтверждённая оригинальная запись DEEP` ≠ `готовый MP4` ≠ `MP4 с проверкой звука` ≠ `MP4 с проверкой видео` ≠ `редакционно одобренный ролик` ≠ `пост в Buffer с ID` ≠ `Buffer sent` ≠ `реально видимый ролик на YouTube`. Каждый переход отдельно фиксируется и проверяется. Зелёный GitHub Action, 150 000 *комбинаций сценариев* и составленный плейлист ничего не доказывают относительно готовых публикаций.

## 3. Резервы и пополнение
- Цель: **10 запланированных уникальных постов в Buffer** (не более лимита бесплатного тарифа), **ещё 10 полностью собранных, прошедших QA и просмотр MP4 вне Buffer**.
- Когда в Buffer остаётся **9 или меньше**, запрашивать пополнение нового десятка подготовленных выпусков; добавлять их в Buffer по мере освобождения слотов. Разрешённые запросы не должны ошибочно называться десятью готовыми видео.
- В банке 100 000+ **неповторяющихся идей/сценариев**; существующие 150 000 адресов не равны 150 000 уникальных видео, событиям, исходным кадрам, голосовым записям или правам.
- При отсутствии реального DEEP, кадров, API или ключа — ясный блокирующий статус, **никогда** голосовая подмена, фиктивный MP4, холостой успех и зацикленный повтор.

## 4. Озвучка
Один-единственный согласованный диктор: **AI Voice Generator / Create Audio Voice, GUSTAVA DEEP**, `voice_id="deep"`, `voice_engine="aidocmaker_deep"`. Запрещены **Silero (все семь голосов), V6, Kokoro Dima** и любой другой «похожий» или искусственно заглублённый диктор. Для каждой новой записи — фактический результат провайдера, URL из доверенного домена, идентичность полного текста, исходный SHA-256, независимый русский ASR и распознавание конечной стереодорожки; никакого проглатывания слов, двойного голоса и перебрасывания между левым и правым каналами. Отсутствующий автономный API для DEEP — **прямой функциональный блокер**, а не подтверждённая работа завода.

## 5. Форматы и сюжет
Изначально утверждённая двадцатка: **35% facts (7), 25% stories (5), 25% experiments (5), 15% spectacle (3)**. Внутри этой сетки сюжеты и темы должны быть реально разнообразными: мотоциклы, люди, локации, последовательность действий, неожиданный момент или полезный вывод. Поздние концепты `4 comedy/3 adrenaline/3 useful` — отдельные предложения для A/B-теста, а **не молчаливая замена** ранее утверждённых 7/5/5/3. Смена сетки — только после проверки равновозрастных данных Shorts и решения владельца.

## 6. Жёсткий контроль качества
Изображение 9:16, 720×1280; без недостроенной рамы, заморозок, тёмных непонятных кадров, повтора A/B/A/B, титров за границей экрана и монтажных скачков каждую секунду. **Рассказанное действие обязательно видно именно на своём временном отрезке** (если речь о шлеме — показываем его, а не произвольный байк). Независимые стоковые сюжеты нельзя выдавать за запись одного события. Источник должен быть реальным, неповторённым, с проверенной лицензией и фактической длительностью. Нужна субъективная проверка кадра, помимо зелёного автоматического QA; плохие кадры не публиковать.

## 7. Публикация и измерение успеха
**Единственный действующий автоматический издатель — Buffer**. Отправлять только оригинальный MP4 после подтверждённых лицензий, точного голоса, исходного и смешанного ASR, визуального QA, проверки кадра и одобрения конкретной редакции. Строго проверять целевой канал, SHA MP4, прежние квитанции и реальный Buffer Post ID; неизвестный исход API не повторять вслепую. Дальше проверять Buffer `sent` и публичную ссылку YouTube, не считать один этап другим. Сохранять логи ошибок и реестр использованных источников, никогда не удалять их ради обхода дедупликации.

Публичные просмотры YouTube ≠ квалифицированные Shorts; Shorts-часы не равны долгим часам YPP. Сравнивать охваты и удержание после **48 часов**, минимум по трём однотипно зрелым Shorts, не обещать заработок; никаких накруток.

## 8. Процесс внесения изменений
1. Прочитать `AGENTS.md`, этот контракт, машинный JSON и актуальные рабочие файлы; по отдельности проверить живые логи GitHub и реальный Buffer.
2. Назвать конкретный провал и тест, воспроизводящий его. Исправлять **один компонент**, не выключая соседние проверки и не меняя голос/раскладку.
3. Вносить через PR и запускать **полный** `test_*.py`, статическую проверку и проверку каталога. Контракт и тесты нельзя изменять молча.
4. Перевести на основную ветку только после зелёного CI. Отдельно проверить реальный MP4, хеш, звук, кадры, Buffer ID и ссылку после выхода. **CI успех ≠ работающая публикация**.
5. В отчёте явно различать `планируется`, `сгенерировано`, `QA`, `одобрено`, `Buffer queued`, `Buffer sent`, `YouTube visible`. При недостатке данных писать **не подтверждено**, а не приписывать успех.

## 9. Текущий функциональный риск
Автоматическое создание **новой** записи AI Doc Maker DEEP через самостоятельный облачный API **не подтверждено**. В `cloud-shorts/production_readiness.py` отмечено `has_autonomous_deep_tts=False`. Чатовая задача с периодической генерацией может помогать, но не является гарантией 10 оригинальных записей/видео в день и не заменяет формальный интерфейс к провайдеру. Резерв сценариев не лечит этот блокер.
