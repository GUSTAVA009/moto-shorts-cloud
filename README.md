# GUSTAVA Enduro — автоматическая фабрика мото-Shorts

**Актуальные правила разработки и выпуска:** [обязательный контракт](docs/FACTORY_CONTRACT_RU.md), [машиночитаемая спецификация](cloud-shorts/factory_contract.json), [память агентов](AGENTS.md). Исторический README от 29 октября не является доказательством живой работы публикаций. Канал:
[YouTube @gustava009](https://www.youtube.com/@gustava009).
Новые видео — **только по мотоциклетной теме**:
эндуро, мотокросс, выезды и путешествия, ремонт и экипировка,
истории реальных мотоциклистов.

**Единственный автоматический сервис публикации — Buffer.**
Ранее использовавшийся сервис публикаций отключён из действующих workflow;
общий контроль качества сохранён в `cloud-shorts/publication_safety.py`.

## Как работает фабрика

```text
Мототема и оригинальная идея
   ↓
Проверка фактов, уникальности, разрешений на исходные кадры
   ↓
GitHub Actions daily-preview → озвучка → музыка → FFmpeg → MP4
   ↓
voice_qa + mixed_audio_qa + editorial_guard + channel_focus
   ↓ (только если все проверки пройдены, выпуск одобрен и не повторяется)
buffer-backlog → GitHub Releases (стабильная ссылка на MP4)
   ↓
Buffer очередь → YouTube GUSTAVA Enduro
```

### Автоматические задачи

- [Ежедневная фабрика MP4](.github/workflows/daily-preview.yml):
  16 окон проверки/рендера через 90 минут; **целевой потолок — 10 новых Shorts в сутки**, без личного контента пользователя и без обещания, что десять готовых MP4 уже созданы.
- [Поиск мотоисторий](.github/workflows/continuous-stories.yml):
  дважды в день, новые идеи проходят проверку перед выпуском.
- [Постановка MP4 в Buffer](.github/workflows/buffer-backlog.yml):
  автоматически после успешного рендера и дополнительно четыре раза в день.
- [Проверка подключения Buffer](.github/workflows/buffer-readiness.yml):
  только чтение реального канала, расписания и количества постов.
- [Полный набор автоматических тестов](.github/workflows/validate-pipeline.yml).

Подробности, диагностика, экстренное отключение автопубликации и ссылки:
**[AUTOPILOT_SETUP_RU.md](AUTOPILOT_SETUP_RU.md)**.

## Защита от ошибок

- Публиковать можно только оригинальные мото-Shorts с `auto_publish:true`,
  **исключительно оригинальным GUSTAVA DEEP**, `voice_engine="aidocmaker_deep"`, `voice_id="deep"`, документированными правами, хеш-подтверждением, фактическим соответствием кадров и полным QA MP4. Отвергнутые Kokoro, Silero и V6 не являются резервными голосами.
- Две дорожки голоса, пропущенные русские слова, недостающие кадры,
  продолжительное зависание изображения и повторные исходники должны
  приводить к отказу от публикации, а не к выдаче дефектного ролика.
- При неопределённом ответе Buffer новая попытка автоматически не делается.
  Реестры сохраняют и старые публикации, чтобы не было дублей.
- Ролики про воду, авиацию, животных и иные посторонние темы
  исключены из активной очереди и заблокированы редакционным фильтром.
- Видео из личных папок Windows и Music Studio не используются.
- Публичные описания без ссылок на исходные видеоматериалы.
- Никаких ботов, накруток, искусственных комментариев или выдуманных просмотров.

## Исторические проверки, не подтверждение текущего конвейера

На 29 октября 2026 года были выполнены следующие разовые проверки:
- действующий ключ Buffer хранится в GitHub Secrets;
- тестовый MP4 загружен в GitHub Releases и принят Buffer как черновик
  (затем тестовый черновик удалён);
- GitHub Actions подтвердил `BUFFER_CREDENTIAL_STATUS READY`;
- тесты проверки исходников, звука, видео и дедупликации прошли;
- последний автоматический поиск готового Shorts сообщил
  `BUFFER_BACKLOG_EMPTY`: **нового одобренного MP4 пока нет**.

**Важно:** успешный workflow не означает, что новое видео опубликовано. Последняя проверка GitHub 31 октября показала `BUFFER_RESERVE_UNDER_MINIMUM: 0/7` и `BUFFER_BACKLOG_EMPTY`, поэтому **автопополнение десяти готовых MP4 и фактическая очередь не были подтверждены**. Документация не должна снова выдавать сценарии или зелёные CI за публикации.

**Согласованная сетка 20 выпусков — 7 фактов / 5 историй / 5 экспериментов / 3 зрелищных сюжета.** Buffer: до 10 поставленных в очередь; при 9 или меньше запросить новый резерв; отдельно целевые 10 полностью проверенных MP4. Автономный программный API создания новых оригинальных DEEP не подтверждён.
Фактическая очередь и даты выхода проверяются в
[Buffer](https://publish.buffer.com/channels/6ae238b32f1f5ed648ff9011/schedule?tab=queue).

## Цель роста

Работаем над 1000 подписчиков и квалификационными порогами YouTube Partner
Program через связку оригинальных Shorts и содержательных длинных мотопрограмм.
Результат зависит от удержания, интереса аудитории, прав и правил YouTube;
10 млн просмотров, 4 тыс. часов и доход не гарантируются.
Метрики для корректировки стратегии берём из YouTube Studio, а не из
публичного счётчика просмотров без проверки квалификации.

Старые инструкции сохранены в истории Git и не являются действующей
конфигурацией проекта.


## Адресуемый резерв 150 000 сценарных вариантов (без внешних ключей)

`cloud-shorts/story_reserve.py` создаёт 150 000 уникальных пар
**заголовок + сценарный текст** по индексу без огромного JSON:
15 мото-тематик × 10 предметов обсуждения × 10 ракурсов ×
10 редакционных выводов × 10 вопросов. Встроенный исчерпывающий
тест проходит все 150 000 адресов, проверяя уникальность и ограничения длины.
Каждый использованный вариант имеет постоянный `story_reserve_id`:
заголовки/идентификаторы повторно не выбираются.

- `python3 cloud-shorts/story_reserve.py --stats` — полная ёмкость.
- `python3 cloud-shorts/story_reserve.py --index 112000` — конкретный текст.
- `daily-capacity` — отдельный показатель оставшихся сценарных вариантов.

Это **сценарные комбинации**, а не 150 000 независимо проверенных реальных
событий, не 150 000 полностью готовых MP4 и не запас уникальных кадров.
Каждый выпуск по-прежнему требует новых лицензированных видеокадров,
содержательной проверки, отсутствия повторов, разборчивой озвучки и QA.
Повторяющийся массово-шаблонный контент не гарантирует монетизацию YouTube.
